% Configuring IP routing on a LAN subinterface is only allowed if that
subinterface is already configured as part of an IEEE 802.10, IEEE 802.1Q,
or ISL vLAN.


if you get this while configuring vlan interfaces, then the issue stems from you not enabling trunking aka 802.1Q on parent interface. just write encapsulation "dot1Q vlanNo. native" (usually default vlan, untagged. Reason it untagged is you don't have vlan management yet, and you send untagged data to a device like pc)


only thing to note with the lab:
as long as your dhcp pool from router for ip phones exists, you got to set option codes to connect to tftp server too. (150. Usually what dhcp codes are for in ccna context).

- as is normal with dhcp, add excluded-range via command:
"ip dhcp excluded-address 10.1.100.200 10.1.100.254" (data vlan)
also for voice vlan. Issue: be careful, since you want to assign specific ip ranges to devices, the ip above will exclude the entire subnet. Example of addressing and networking application in dhcp configuration...


SWITCH CONFIG

often times, telephony may not work. So just shut down some ports and enable them again.

- ENABLING CDP:
"cdp run"
(enables cdp)

"show cdp neighbors"

- do int range 1/0/2-4 since you want to apply similar config to all neighbors 

- switchport mode access. then switchport voice vlan 101 (since data ran thru router untagged).
> this command is particularly interesting because actually it configures static access on cpt not access.
> allows both tagged/untagged data: special type of access port.


- remember when it was noted that switchport used to be configured as trunk for ip phones, but had broadcast issues. So what was done?
They pruned trunk port to only accept tagged and untagged vlan data with switchport static access (enabled from mode access).

odd phrasing but gets function accross: "access auto pruning trunk port"

- show cdp neighbors

- then show power inline
answers a requirement. 10W is drawn from switch with more avail.

MAKE TELEPHONY SERVICE

- at end they should get ips.

- if you make addressing mistake, often phones may have trouble getting ips.

#telephony-service 
Router(config-telephony)#max-ephones 3
Router(config-telephony)#max-dn 3

addressing: ip source-address IPNo. port 2000

- auto assign 1 to 3 
(as many as you have on switch)

after exiting telephony config:
#ephone-dn 1
Router(config-ephone-dn)#%LINK-3-UPDOWN: Interface ephone_dsp DN 1.1, changed state to up
Router(config-ephone-dn)#number 1000

exit ephone-dn config. now the phone will be registered.

CONFIGURING EPHONE SERVICE USING ROUTER CUCM

- "ephone No."

- inside ephone config (not same as ephone dn), specify "ephone type"

- "type 7960", an old, very common ephone type (or legacy)

- "button X:X" 1:1, aka button 1 to dn1, 2nd to 2nd and so on..

- an amazing thing: with auto assign, you don't need to configure prices.

- exit to continue checking/configuring for the rest

fact: if phones not binded to dhcp of router, they won't get telephony service.

important: if you face issue, good tip is troubleshooting. At this point, restart cpt but not before you write on every NMS device.
